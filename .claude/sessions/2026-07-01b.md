# Session Log — 2026-07-01 (part 2)

## Summary
Deep SPA refactoring — removed all window globals, wired components via typed bridge module.

## Root Problem
After pages were merged into a single-page Angular app, the D3 provenance-tree-visualization
library could no longer reliably access Angular services via window globals. The lib used:
- window.canvas.provenance.xxx() — to call ProvenanceService methods
- window.slideDeck.xxx() — to add/remove nodes from story deck

Angular components set these globals in ngOnInit, but in SPA context the timing was fragile
and the references could be stale or missing after graph resets.

## Changes Made

### New file: `frontend/provenance-tree-visualization-grouping/src/bridge.ts`
- Typed module-level singleton `storyVisBridge: IStoryVisBridge`
- Fields: `provenance` (ProvenanceService interface) + `slideDeck` (SlideDeckVisualization interface)
- Angular sets these after service/component init; lib reads lazily via optional chaining

### `frontend/provenance-tree-visualization-grouping/src/components.ts`
- Added import of storyVisBridge
- 6 calls replaced: generation(), fission(), splitting(), saveGraph(), saveStory()
  from window.canvas.provenance.xxx → storyVisBridge.provenance?.xxx()

### `frontend/provenance-tree-visualization-grouping/src/controls.ts`
- Added import of storyVisBridge
- 4 keyboard shortcut calls replaced: window.slideDeck.onAdd → storyVisBridge.slideDeck?.onAdd()

### `frontend/provenance-tree-visualization-grouping/src/provenance-tree-visualization.ts`
- Added import + re-export of storyVisBridge
- contextmenu handler: window.slideDeck.onAdd/onDelete → bridge

### `frontend/storyvis/src/app/shared/_services/provenance.service.ts`
